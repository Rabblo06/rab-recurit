## 3. Push notifications (iOS)

- **Owner-approved architecture:** "durable offline push notifications (owner-approved: FCM for Android, direct APNs for iOS)" (HANDOFF Stage 6, ~line 3997).
- **Verified in server code:** `PUSH_PROVIDER=REAL` routes `platform:"android"` → `FcmDriver` (firebase-admin, FCM HTTP v1) and `platform:"ios"` → **`ApnsDriver` — direct HTTP/2 to `api.push.apple.com` / `api.sandbox.push.apple.com`, ES256 provider JWT** (`engine/core-modules/push/drivers/apns.driver.ts`, `push-driver.factory.ts:81-97`). Firebase is **not** used for iOS and must not be: do not send an FCM token with `platform:"ios"`.
- **Status:** APNs driver "IMPLEMENTED at the backend driver level only, not device-verified, NOT WIRED on the Flutter side"; production rollout "NOT READY" (HANDOFF ~4026-4035, 4079-4085). Defaults: `PUSH_ENABLED=false`, `PUSH_PROVIDER=FAKE` (nothing delivered).
- **Needed before iOS push works end-to-end (owner):** Apple Developer account, APNs auth key (`.p8`) → `APNS_AUTH_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID`; `APNS_BUNDLE_ID` = the iOS bundle id; `APNS_ENVIRONMENT` matching the build (sandbox for dev-signed, production for TestFlight/App Store — a single server env cannot serve both at once); `PUSH_ENABLED=true`, `PUSH_PROVIDER=REAL`; Push Notifications capability/entitlement in the Xcode project.
- **Flutter today:** Android-only (`Platform.isAndroid` gate); there is no Flutter iOS project.

## 5. Owner decisions still open that affect mobile behaviour (from HANDOFF)

- Check-in rollout rule (existing bookings keep old flow), check-in window = clock window, evidence max age 120 s / skew 30 s, accuracy cap min(100 m, radius), on-behalf clock-in presence rule, on-behalf clock-out refused at enforcing venues, checked-in staff never auto-flagged, `filled` includes provisional no-shows.
- Manual attendance: time bounds (QR window), reason list, VM reopen allowed before finalisation only, confirmation earliest at start + 30 min.
- Standby/replacement wording, expiry, urgent-replacement window.
- `payroll.approve` 2FA (not enforced), back-fill of reports finalised before payroll migration, rejected-payroll reopen / post-approval adjustment path.
- Money display assumption: 0-pence rate shows "Rate not set" (Flutter `money.dart`, flagged).
