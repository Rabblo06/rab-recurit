`packages/rab-server/src` has two halves. Dependencies only flow from `modules/` to `engine/`.

## engine/ — platform machinery

| Module | Responsibility |
| --- | --- |
| `core-modules/auth` | Password and OIDC sign-in, sessions, refresh rotation, password reset, invitations, application access. |
| `core-modules/tenant` | `TenantContextService` — binds organisation, workspace and user into each transaction. Workspace membership resolution. |
| `guards` | `JwtAuthGuard` chain, `PermissionGuard(flag)`, `RequireWorkspaceGuard`, `PlatformAdminGuard`. |
| `core-modules/audit` | Append-only audit log. |
| `core-modules/storage` | `FileService`, local and S3 drivers, file access registry. |
| `core-modules/email` | Durable email outbox, BullMQ producer, drivers, templates. |
| `core-modules/push` | Device registration and push delivery records. |
| `core-modules/realtime` | Realtime outbox and the SSE gateway. |
| `core-modules/platform-admin` | Admin Panel, organisation suspension, inspection sessions. |
| `core-modules/environment` | Validated configuration. |
| `core-modules/throttler` | Redis-backed rate limiting (default 120 requests/minute per IP). |
| `core-modules/health` | `GET /healthz`. |

## modules/ — the staffing domain

| Module | Responsibility |
| --- | --- |
| `identity` | Profiles, preferences, sessions list, workspace settings, roles. |
| `manager` | Managers, venue managers, CEO creation rules, organisation onboarding. |
| `manager-workspace` | Workspace creation, subdomains, onboarding completion. |
| `staff` | Staff records, invitations, venue directory and teams. |
| `venue` | Venues, geofence settings, role pay rates. |
| `scheduling` | Job roles, shifts, venue shift requests, cancellation, rate resolution. |
| `offer` | Offers, batches, confirmation, replacement requests, live staffing pipeline. |
| `attendance` | Clock-in/out, QR tokens, geofence, corrections, shift reports. |
| `notification` | In-app notifications and preference-aware fan-out. |
| `dashboard`, `search` | Summary and global search, gated per section by permission. |

## Rules that apply to every service

- **Business logic lives in services.** Controllers are transport adapters; the Worker calls the same services.
- **Service-level permission checks.** A service re-checks scope even when a guard already did, because jobs and CLI commands never pass a guard.
- **Explicit DTO mapping.** `class-validator` with `forbidNonWhitelisted: true` rejects unknown fields (including `organisationId` and `status`). Never spread a client object into an entity.
- **State transitions through `assertTransition`.** Unknown transitions throw `InvalidTransitionError` (409).
- **Rate snapshotting.** The pay rate is resolved when an offer is sent (shift override → venue role rate → job role default) and stored on the assignment; it is never recalculated.

```ts title="modules/offer/controllers/offer.controller.ts"
/** Step 2 of 2 — manager-only, only valid from STAFF_ACCEPTED. This is the only path to MANAGER_CONFIRMED. */
@Post('offers/:id/confirm')
@ManagerApplication()
@UseGuards(PermissionGuard(PermissionFlag.OFFER_CONFIRM))
confirm(@AuthUser() ctx: AuthContext, @Param('id') id: string) {
  return this.offerService.managerConfirm(ctx, id);
}
```

The controller only declares the guard and delegates. `OfferService.managerConfirm` loads the offer under the caller's tenant context (404 if out of scope) and validates the `staff_accepted → manager_confirmed` transition (409 otherwise). `JwtAuthGuard` is applied at the controller class level.
