```text
├── rab-front/         Web console (React + Vite)
├── rab-mobile/        Mobile app (Flutter) for staff and venue managers
├── rab-shared/        Types, permission flags, state machines, money and duration utilities
├── rab-ui/            Design tokens

├── rab-utils/         Small shared helpers
├── rab-e2e-testing/   Playwright web specs and a Maestro-style mobile flow
├── rab-docker/        Dockerfile, start scripts, Compose files, Postgres init roles
├── rab-readme/        README images
├── rab-website/       Separate marketing website (not part of the product)
└── crewflow-docs/     This documentation site (Mintlify)
```

## Workspaces and Nx

- Yarn workspaces are an **explicit list** in the root `package.json`: `rab-server`, `rab-worker`, `rab-front`, `rab-shared`, `rab-ui`, `rab-emails`, `rab-e2e-testing`, `rab-utils`.
- `rab-mobile`, `rab-docker`, `rab-readme`, `rab-website` and `crewflow-docs` are **not** Yarn workspaces.
- Nx discovers projects from the workspaces; targets are defined in each package's `project.json`.

## Dual-published shared libraries

`@rab/shared` and `@rab/ui` are imported by Node (`rab-server`) and by Vite/browser consumers, so each is built twice:

| Build | Config | Output | Consumer |
| --- | --- | --- | --- |
| ESM | `tsconfig.lib.json` | `dist-esm/` | `rab-front` (Vite) |
| CommonJS | `tsconfig.lib.cjs.json` | `dist-cjs/` | `rab-server`, `rab-worker` |

The `exports` map selects the build. `dist-cjs/package.json` contains `{"type":"commonjs"}` so Node does not treat those files as ESM. Copy this pattern for any new library shared between server and clients.

## Backend module shape

Every domain module under `rab-server/src/modules/` uses the same layout:

```text
modules/<domain>/
├── <domain>.module.ts
├── controllers/   # transport adapters only
├── services/      # all business logic
├── entities/
├── dto/           # class-validator, forbidNonWhitelisted
├── jobs/
├── listeners/
├── constants/
├── exceptions/
└── __tests__/
```

Controllers never contain business logic, so a rule enforced for the web console cannot be missing for mobile.

## Client feature folders

Both clients are organised **by feature**, not by file type:

- `rab-front/src/features/<domain>/` — auth, onboarding, dashboard, users, scheduling, offers, venues, payroll, audit, notifications, settings, ai.
- `rab-front/src/shared/` — only code used by three or more features (API client, theme, generic UI).
- `rab-front/src/shell/` — app chrome (Layout, AdminDropdown, GlobalSearch, CommandPalette). It may import features; features never import the shell.
- `rab-mobile/lib/features/<domain>/` — the same rule for Flutter.
