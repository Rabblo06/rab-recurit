Crewflow handles people's personal details, working hours and pay. Its security is built in layers, so no single mistake exposes data.

## The principles

| Principle | In practice |
| --- | --- |
| **Identity comes from the server** | Who you are, your organisation and your workspace are taken from your verified session — never from what an app sends. |
| **Every layer checks** | A request passes the sign-in check, the permission check, the service's own check and the database's row-level rules. Each would stop it on its own. |
| **Fail closed** | If something cannot be checked, the answer is no. A database query with no verified workspace returns nothing at all. |
| **Don't reveal what you can't see** | A record outside your scope is reported as "not found", so its existence is never confirmed. |
| **Actions, not raw changes** | The apps ask for named actions such as "confirm offer"; they cannot set a record's status directly. Invalid changes are refused. |
