The API validates its environment when it starts (`packages/rab-server/src/engine/core-modules/environment/environment-variables.ts`, checked by `env.validation.ts`). Missing or invalid configuration stops the process — it never boots half-configured. The full annotated template is `packages/rab-server/.env.example`.

<Warning>
  This page lists variable **names** only. Keep values in your deployment platform's secret store or an untracked `.env` file.
</Warning>

<Note>
  **On/off switches are strict.** Every boolean variable (`…_ENABLED`, `EMAIL_SMTP_NO_TLS`, `WORKER_FAST_PUBLISH_NOTIFY`, …) accepts exactly `true` or `false`, lower case. Unset or empty keeps the default. Anything else (`True`, `1`, `yes`, a typo) stops the process at boot. `AI_AGENTS_ENABLED` is the one exception: any value other than `true` means off. See `packages/rab-docker/docs/release/RELEASE-NOTE-X3.1-STRICT-BOOLEANS.md`.
</Note>

## Required

| Variable | Purpose |
| --- | --- |
| `PG_DATABASE_URL` | The one database setting of a deployment (`compose.env`): your PostgreSQL's admin URL, an existing `crewflow_owner` URL, or unset for the bundled `db` (`PG_DATABASE_PASSWORD`). Only the one-shot `db-setup` service receives it; the API and the Worker refuse it and build the `crewflow_owner` URL from `db-setup`'s target file and its `crewflow_owner` password file (a random password, kept on `db-setup`'s volume). In local development a process reads it directly. The deprecated `DATABASE_URL` is refused in production and by the API and the Worker in every environment; local CLI, migration and test runs outside production still accept it with a warning this release. |
| `REDIS_URL` | Redis for queues, rate limiting and caches. |
| `APP_SECRET` | Root secret; also used to derive the shift QR signing key. Never part of a database credential: changing it never touches the database. |

## Core

`NODE_ENV`, `PORT`, `APP_VERSION`, `SENTRY_DSN`, `CORS_ORIGINS`, `TRUSTED_PROXY_CIDRS`, `APP_URL`, `ACCOUNTS_URL`, `WORKSPACE_BASE_DOMAIN`.

- `APP_URL` is the web console's address; `ACCOUNTS_URL` hosts activation and password-reset pages and may be a separate domain.
- `CORS_ORIGINS` is an explicit allowlist. Workspace subdomains of `WORKSPACE_BASE_DOMAIN` are also trusted (HTTPS only in production).

## Keys and rotation

`APP_ENCRYPTION_KEYRING`, `APP_ENCRYPTION_ACTIVE_KID`, `APP_JWT_SIGNING_KEYRING`, `APP_JWT_ACTIVE_KID`.

Rotate by adding the new key to every instance's keyring first, confirming with `secret:rotate --check-keyring` on each instance, and only then switching the active key ID.

## Authentication providers

| Variable | Default |
| --- | --- |
| `AUTH_PASSWORD_ENABLED` | `true` |
| `AUTH_GOOGLE_ENABLED`, `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET`, `AUTH_GOOGLE_CALLBACK_URL` | disabled |
| `AUTH_MICROSOFT_ENABLED`, `AUTH_MICROSOFT_CLIENT_ID`, `AUTH_MICROSOFT_CLIENT_SECRET`, `AUTH_MICROSOFT_CALLBACK_URL`, `AUTH_MICROSOFT_TENANT` | disabled; tenant `organizations` |

Boot fails if every provider is disabled, or if enabling a provider leaves its client settings empty.

## Business rules

| Variable | Default | Meaning |
| --- | --- | --- |
| `CLOCK_IN_EARLY_MINUTES` | 15 | How early clock-in opens. |
| `CLOCK_IN_CONFIRM_FLOOR_HOURS` | 12 | Hard floor (1-48 hours before the staff member's start) for a manager-entered clock-in; between it and `CLOCK_IN_EARLY_MINUTES` the manager must confirm. |
| `QR_POST_SHIFT_GRACE_MINUTES` | 120 | How long after the end clock-in/out stays open. |
| `REPORT_AVAILABLE_BEFORE_MINUTES` | 180 | When the roster PDF is produced. |
| `PDF_RENDERER` | `native` | How the Worker renders report PDFs: `native` (pure JavaScript with `@react-pdf/renderer`, no browser) is the only accepted value. The Chromium renderer was retired (P5) and the Worker image contains no browser, so `chromium` or any other value refuses to boot. Leave it unset. |
| `GEOFENCE_MAX_ACCURACY_M` | 100 | Worst acceptable GPS accuracy at enforced venues. |
| `LATE_CLOCK_IN_GRACE_MINUTES` | 10 | When a confirmed person counts as late. |

`MANAGER_CONFIRMATION_TIMEOUT_MINUTES` no longer exists: Crewflow never confirms an offer automatically, and the manager-confirmation deadline (30 minutes before a standard offer's start) is fixed, not configurable. A deployment that still sets it keeps booting; the value is ignored. `WORKER_MANAGER_CONFIRMATION_TIMEOUT_INTERVAL_SECONDS` still sets how often the Worker checks for passed deadlines.

## Worker shutdown

`WORKER_SHUTDOWN_TIMEOUT_MS` (default 30000) is how long the Worker waits, after SIGTERM, for its active jobs and in-flight cycles before it exits anyway. It must be a plain integer from 1000 to 34000: the drain plus the Worker's 10-second hard-exit margin has to end inside the Worker's `stop_grace_period: 45s`, or Docker kills a job mid-drain. Anything else refuses to boot, including a value with a unit such as `30s` and a value with a trailing carriage return (`30000\r`, from an env file saved with Windows CRLF line endings).

## Feature flags (all default `false`)

`HWS_RUNTIME_ENABLED`, `AUTH_CONTEXT_CACHE_ENABLED`, `USER_SESSION_CACHE_ENABLED`, `CORE_ENTITY_CACHE_ENABLED`, `WORKSPACE_METADATA_CACHE_ENABLED`, `USER_SESSION_ENFORCEMENT_CUTOVER`, `REALTIME_ENABLED`, `PUSH_ENABLED`.

## Real-time and push

`REALTIME_HEARTBEAT_INTERVAL_MS`, `REALTIME_MAX_CONNECTIONS_PER_USER`, `REALTIME_MAX_CONNECTIONS_PER_INSTANCE` (both caps count per API instance), `PUSH_PROVIDER`, `FIREBASE_SERVICE_ACCOUNT_JSON`, `APNS_AUTH_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_BUNDLE_ID`, `APNS_ENVIRONMENT`, `PUSH_DELIVERY_MAX_ATTEMPTS`.

## AI

| Variable | Default | Notes |
| --- | --- | --- |
| `AI_ENABLED` | `true` | Platform kill switch. Production compose commits `${AI_ENABLED:-false}`: off unless the operator sets `AI_ENABLED=true`. Every organisation's own AI switch still starts off. |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_API_KEY`, `MISTRAL_API_KEY`, `XAI_API_KEY` | empty | Secret; shown as "configured" only. Only Anthropic's SDK is in this build. See [How to add or rotate an AI provider key](/developers/ai-provider-keys). |
| `AI_MODELS_DEFAULT_FAST`, `AI_MODELS_DEFAULT_SMART` | empty | Catalogue ids used when an organisation has not chosen a model; the first available wins. |
| `AI_MODELS_DEFAULT_DISABLED` | empty | Catalogue ids nobody may use. |
| `AI_DEV_ALLOW_REAL_PROVIDERS` | `false` | Development only; refused at boot in test and production. |
| `AI_DAILY_BUDGET_USD` | `2` | Estimated provider cost per organisation per day; reserved before every model step. |

`AI_PROVIDER`, `AI_MODEL` and `AI_PROVIDER_API_KEY` are retired. The model is chosen per organisation in Settings → AI.
A mock value refuses to boot outside tests, and the old key name refuses to boot in development.

## Read outside the validated schema

| Variable | Used by |
| --- | --- |
| `PG_POOL_MAX_CONNECTIONS`, `PG_POOL_IDLE_TIMEOUT_MS`, `PG_POOL_ALLOW_EXIT_ON_IDLE`, `PG_DATABASE_PRIMARY_TIMEOUT_MS` | Pool size and timeouts (strictly validated). |
| `PG_SSL_CA_CERT_PATH`, `PG_SSL_ALLOW_SELF_SIGNED`, `PG_DATABASE_URL_IS_DIRECT` | TLS (production: verify-full only) and the direct-connection declaration. |
| `PG_DATABASE_REPLICA_URL`, `PG_DATABASE_REPLICA_TIMEOUT_MS`, `PG_DATABASE_REPLICA_MAX_LAG_MS` | Optional read replica. |
| `CREWFLOW_DEPLOYMENT_ENVIRONMENT`, `CREWFLOW_DEPLOYMENT_ID`, `PG_EXPECTED_DATABASE_NAME` | Deployment identity, compared with the database's protected marker (required in production). |
| `DATABASE_URL_UNPOOLED`, `DATABASE_DIRECT_URL`, `DB_POOL_MAX` | Deprecated: use `PG_DATABASE_URL` and `PG_POOL_MAX_CONNECTIONS`. Refused in production; `DATABASE_URL_UNPOOLED` and `DATABASE_DIRECT_URL` are also refused by the API and the Worker in every environment. Local CLI and migration runs outside production still accept them with a warning this release (`PG_LEGACY_NAMES_STRICT=true` refuses them there too). |
| `WORKSPACE_PROVISIONER_INTERVAL_SECONDS` | How often the Worker's in-process workspace provisioning polls (5 to 120, default 60). Every `CREWFLOW_PROVISIONER_*` name is refused on the API and the Worker. See [Deployment](/developers/deployment#environment). |
| `BOOTSTRAP_ADMIN_EMAIL` (optional `BOOTSTRAP_ADMIN_FIRST_NAME`, `_LAST_NAME`, `_ORG_SLUG`, `_ORG_NAME`) | The first platform administrator. rab-api creates it at start when no platform admin exists yet, and the `bootstrap-admin` command does the same. One activation email goes to that address (the link expires after 24 hours). The API refuses unless , so the admin must set up two-factor authentication at first sign-in. Once an admin exists the variable does nothing and can be removed. rab-api only. `BOOTSTRAP_ADMIN_PASSWORD` is refused. |
