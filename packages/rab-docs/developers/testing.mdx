## Run the tests

```bash
yarn test                                     # every Jest suite in the monorepo
npx nx test rab-server                        # API unit + integration tests
npx nx test rab-worker
npx nx test rab-shared
npx nx e2e rab-e2e-testing                    # Playwright web specs
```

From `packages/rab-mobile`:

```bash
flutter analyze
flutter test
```

## Integration test identities

Integration tests use real role keys from `src/__tests__/integration/helpers/test-identities.ts`, so permission checks run exactly as in production. Point them at a dedicated test database with `TEST_DATABASE_URL` (runtime role) and `TEST_DATABASE_ADMIN_URL` (the disposable test cluster's bootstrap superuser, used only for fixtures, identity probes and migrations; its old name `TEST_DATABASE_URL_UNPOOLED` is still accepted this release with a deprecation line, and setting both to different values is refused). The Jest setup maps them onto the deprecated `DATABASE_URL` / `DATABASE_URL_UNPOOLED` names for the test process only. Jest refuses to start unless `NODE_ENV=test` (a `NODE_ENV=development` in `packages/rab-server/.env` is refused, not ignored), and refuses an inherited `PG_DATABASE_URL`, `DATABASE_DIRECT_URL`, `PG_DATABASE_REPLICA_URL` or `PG*` libpq variable that names another database, as well as the development database itself (`devdb`, 127.0.0.1:15432); leave those unset for a Jest run. The Phase D worker-login switch (`TEST_DATABASE_WORKER_URL`, used when `PHASE_D_SQL_APPROVED=true`) goes through the same checks whatever `NODE_ENV` says, and may not be the superuser login of `TEST_DATABASE_ADMIN_URL` (or its old name). The AI e2e harness starts the API, Worker, Vite and Playwright without that superuser URL, under any variable name.

<Warning>
  Never point test variables at a shared or production database. Tests create and remove data.
</Warning>

## The testing floor

Every change that touches authorisation, tenancy or a state machine must include the **denial** test, not only the happy path. The abuse-case suites (`*-abuse-cases.integration.spec.ts`) are the model:

| Case | Expected |
| --- | --- |
| Staff A reads Staff B's attendance | 404 |
| Organisation A reads Organisation B's record by ID | 404 |
| Staff confirms their own accepted offer | 403 |
| Manager confirms a still-pending offer | 409 |
| Request body contains `status` or `organisationId` | 400 |
| Unauthenticated request | 401 |
| Query with no tenant context bound | 0 rows |
| Direct `audit_log` update or delete | Database permission denied |

Every new tenant-scoped table also needs an integration test that queries with no tenant context and asserts zero rows. `yarn check-rls` must pass.

## Flutter goldens

Golden images under `packages/rab-mobile/test/goldens/` are compared pixel by pixel. Never regenerate goldens without inspecting the differences.
